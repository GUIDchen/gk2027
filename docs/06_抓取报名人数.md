# 抓取报名人数

> 数据来源：登录后的“职位查询 → 按代码选择职位”页面背后的职位详情接口。
> 工具只读取数据，不修改报名信息。

## 一、抓取前准备

1. Chrome 打开 <https://bm.scs.gov.cn/kl2027> 并完成登录；
2. 进入 **个人中心 → 职位查询 → 按代码选择职位**，保持页面打开；
3. Chrome 菜单栏：**显示 → 开发者 → 勾选“允许 Apple 事件中的 JavaScript”**；
4. 运行：

```bash
./run.command doctor
./run.command fetch --label 10-23
```

`doctor` 会检查：Chrome 是否运行、是否有 `person_position.html` 页面、页面脚本能否执行。

## 二、命令参数

```bash
./run.command fetch --label 10-23
./run.command fetch --label 10-23 --workers 3 --retries 2
./run.command fetch --label 10-23 --out data/counts/counts_2026-10-23.json
```

| 参数 | 默认 | 说明 |
|---|---|---|
| `--workbook` | 配置里的工作簿 | 从中读取“符合条件岗位” |
| `--label` | 当天 MM-DD | 快照标签 |
| `--out` | `data/counts/counts_日期.json` | 原始 JSON 输出 |
| `--workers` | 3 | 并发数；系统慢时降到 2 |
| `--retries` | 2 | 单条失败重试次数 |

## 三、它做了什么

1. 从工作簿读取 1,034 个符合条件岗位（部门代码 + 职位代码）；
2. 检查页面脚本与登录接口（单条探测，401 会直接提示重新登录）；
3. 把岗位分块注入页面（每块 150 个），避免一次注入过大；
4. 3 路并发请求职位详情接口，失败重试 2 次；
5. 结果写入页面隐藏 textarea，按 40KB 分块读回；
6. 保存为 `data/counts/counts_YYYY-MM-DD.json`，并清理页面临时元素。

## 四、常见错误

| 提示 | 原因 | 处理 |
|---|---|---|
| `HTTP 401` / 登录会话已失效 | 登录过期 | 重新登录，打开职位查询页后重试 |
| `__NOT_FOUND__` / 找不到页面 | 没有打开 `person_position.html` | 打开“按代码选择职位”页面 |
| `通过 AppleScript 执行 JavaScript 的功能已关闭` | Chrome 未勾选 JS 自动化 | 显示 → 开发者 → 勾选 |
| `HTTP 0` | 并发过高/网络抖动 | 降低 `--workers 2`，或重跑 |
| 抓取超时 | 系统慢/页面被关闭 | 保持页面打开，重跑 |

## 五、数据口径

- `book` = 系统返回的报名总数（`num`）；
- 详情接口没有返回“待审查/审查通过”分项，所以只列总数；
- 报名人数会随报名进程变化，以系统实时为准；
- 10-23 各职位更新时间集中在 13:05—16:03，抓取时间约 16:00。

## 六、隐私

- 使用**自己的** Chrome 登录；工具不会上传/共享账号；
- 抓取结果只有职位代码和报名人数，不含个人信息；
- `data/counts/` 已被 `.gitignore` 排除。
